# AgentDesk 技术路线与选型记录

## 为什么 MVP 选择 RAG

企业 IT 服务台需要可解释、可审计和可控的回答。MVP 使用“文档解析 → Markdown 归一化 → 分段 → PostgreSQL 全文检索 → 引用式草稿”的 RAG 流程，优先满足成熟度、响应速度和引用可追踪性。当前没有把回答准确率承诺为固定比例；无命中时必须拒答或转人工。

LLM Wiki 的长期记忆和自动组织能力值得跟踪，但当前开源实现缺少企业常用的权限、合规和审计能力，所以只在报告中作为后续路线，待企业版能力稳定后重新评估。

## 产品对比

| 类别 | 代表产品 | 本项目结论 |
| --- | --- | --- |
| 企业 RAG | FastGPT 商用版、腾讯开源 Vicuna | 可作为外部方案对比；本项目自建最小闭环，避免外部产品锁定 |
| 个人知识库 | Obsidian | 适合个人本地使用，不作为企业权限和审计底座 |
| 尝试类 | Dify、毕升 | 可用于调研，不作为课程项目主路线 |
| LLM Wiki | 新兴开源项目 | 记录优缺点，暂不纳入 MVP |

## 底层能力

PDF、DOCX、Markdown 和 TXT 通过解析适配器归一化到 Markdown；课程材料中“Mano u”“Dockling”按上下文校正为 MarkItDown、Docling。MinIO 保存原始附件，PostgreSQL 保存文章版本、标签和检索索引，未来可增加 pgvector 或 OpenSearch。

## 治理优先级

知识入库必须经过审核，文章拥有版本、标签、可见范围和发布状态；过期内容下线后不得参与检索。Agent 的建议和写入动作都保存输入摘要、证据、工具调用、输出、耗时、错误及人工决定。
