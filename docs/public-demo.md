# AgentDesk 公开演示指南

这份指南适合在面试、答辩或向招聘者展示项目时使用。推荐先展示流程，再补充代码结构和设计取舍。

## 1. 先讲业务问题

“员工遇到 IT 问题时，系统要先帮助他自助找到有证据的答案；如果仍然解决不了，就把问题转成可追踪工单；AI 可以减少分类和撰写时间，但关键动作必须由人确认，所有结果都能审计。”

## 2. 推荐展示顺序

1. **管理统计**：从 \`docs/images/dashboard.png\` 说明工单量、SLA、趋势和优先级分布。
2. **知识版本**：展示文章从草稿到发布、编辑生成新版本、撤回后不再参与检索。
3. **文档导入**：展示批次上传、解析、分块、索引、失败重试和事件进度。
4. **员工问答**：提出“VPN 认证超时”类问题，展示引用先到、回答后到，以及点击引用跳转到文章分块。
5. **转人工**：无证据时拒答或转工单，展示请求人只能看到自己的数据。
6. **人工审批**：让 Agent 提议转交/关闭，管理员审批后执行，最后打开审计日志。

## 3. 面试时可主动强调的细节

- 为什么使用 PostgreSQL FTS + 可选 pgvector：先把可解释、可回退的主链路做好，再增加语义召回。
- 为什么 AI 不直接操作工单：将生成式输出与业务写操作隔离，用待审批状态保护可逆性和审计性。
- 如何避免“只在前端隐藏按钮”：权限条件在后端列表、详情、搜索、问答和附件接口统一执行。
- 如何处理长查询：AND 精确召回不足时在查询级放宽为 OR，而不是破坏所有查询的精度。
- 如何验证：纯函数/服务单测、前端 SSE 确定性测试、冒烟脚本、端到端脚本分层，明确哪些依赖真实 Docker 栈。

## 4. 展示边界

仓库中的图片是本地演示快照，账号身份和凭据已经遮挡；不要把本地 \`.env\`、真实企业资料、真实用户数据或生产数据库导出上传到公开仓库。
