# 功能补全与历史验证记录（公开版）

后续进展：2026-09-28 已刷新最终构建、重跑真实 HTTP 流程并验证 DeepSeek 工单闭环，见[新记录](verification-2026-09-28.md)。以下保留 9 月 22 日当时的证据和限制。

本记录整理 2026-09-22 开发版的功能补全和当日验证证据。公开版移除了本机文件路径、临时测试账号文件链接和个人工作区信息。这里的测试数是历史结果，不能代替后续对当前代码的完整运行验收。

## 功能变化

| 场景 | 行为与边界 |
| --- | --- |
| 员工查看文章 | 员工只能读取有权访问的当前发布版本；草稿、驳回版本和归档历史版本不可读。旧引用失效时可返回当前发布版本。 |
| 原件查看与下载 | 原件通过版本记录的来源导入项绑定。指定版本的 PDF 预览和下载使用同一版本；无法确认历史绑定关系时不猜测归属。 |
| 管理员编辑已发布文章 | 正文修改生成草稿，旧发布版本在审核期间继续供员工查看和检索。新版本、分块和编辑数据以事务保存，向量化在事务后处理。标题、标签和权限元数据仍属于文章级设置。 |
| 管理员审核新稿 | 审核请求携带已查看的版本和文章状态；期间出现新版本或文章撤回时返回冲突，要求重新查看。驳回新稿不会下线旧发布版本。 |
| 待审文章列表 | 管理员筛选待审核内容时可找到仍在线文章的新稿；员工响应不暴露待审版本 ID。 |
| 重复文件与批次发布 | 同 SHA 文件处理以 PostgreSQL 事务锁协调；同批次同文章仅发布最新版本。旧草稿归档、过期待审导入项取消；整批发布在一个事务中完成，进度事件在提交后发送。 |
| 处理人审批 | 新增 `/workspace/approvals` 页面。管理员与所属队列处理人可查看获授权的待审批动作、打开工单并批准或驳回；普通员工无权访问。 |
| 新建部门 | V18 将部门自增序列调整到现存最大 ID 之后，避免固定种子 ID 与新部门编号冲突。 |
| 自定义端口登录 | Nginx 转发保留 Host 端口和来源协议，浏览器登录请求携带匹配的 Origin。 |
| AI 对照评估 | 新增 24 条合成案例、2 组版本化 Prompt、模型调用和 JSON/CSV/Markdown 导出脚本。默认命令离线校验；只有显式使用 `--run` 才会调用 OpenAI 兼容模型。 |

## 数据兼容

- 新增 Flyway V17/V18，不改写已经执行过的 V1–V16。部署新版后由 Flyway 执行新增迁移，前端也需一并更新才能使用审批与版本入口。
- V17 只自动绑定关系明确的历史原件；无法可靠确认的记录保持未绑定，没有删除历史文件。
- 员工只能访问当前发布版本；管理员仍可访问其权限范围内的草稿与版本历史。这是有意收紧的读取边界。
- 审核仍由有权限的人员确认，没有增加双人复核要求。

## 当前验证边界

真实 LLM 效果评估与完整全链路录屏不属于 2026-09-22 历史证据。2026-09-28 本轮运行证据由主代理另行补充；截至本文件整理时，没有可引用的完整全链路录屏结果。本次公开同步准备没有运行项目测试或录屏。

评估框架离线复现：

```powershell
python scripts/evaluate-ai.py --validate-only
python scripts/test-evaluate-ai.py
```

真实模型运行必须显式设置 `AI_EVAL_API_KEY`、`AI_EVAL_BASE_URL`、`AI_EVAL_MODEL` 后执行 `python scripts/evaluate-ai.py --run`。脚本不会读取 `.env`；API 错误和空输出不计作正确拒答，规则分数需要人工复核，不能冒充模型准确率。

真实 HTTP 脚本 `scripts/knowledge-http-verify.py` 只能对明确隔离的测试环境运行；需要确认使用 `agentdesk_test` 和专用隔离容器，禁止指向业务数据库或默认演示栈。脚本生成的账号、日志与结果写入被 Git 忽略的 `verification-output/`，需要保留时应由操作者另行归档。
