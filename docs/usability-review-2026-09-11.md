# AgentDesk 可用性审查与优化记录

审查日期：2026-09-11。范围：员工求助、工单处理、问答、通知、首次启动与前端性能。

## 当前结论

本轮重点把已有功能连成可操作的流程，并修复代码中确认存在的故障和权限问题。功能变多不等于产品好用；用户最在意的是能否快速找到入口、完成处理，以及失败后还能继续。

**代码优化和独立测试已完成，真实全栈验收尚未完成。** 首次 Docker 构建遭遇本机内存不足，随后 Docker 因异常通信文件无法重新启动。恢复操作被自动审批策略拒绝。本轮没有删除 Docker 数据或重置环境，也没有把模拟接口验收写成真实接口通过。

本报告中的“已修复”表示代码已修改并经过相应检查；涉及数据库事务、文件存储、实际模型和代理的功能，仍须执行下方真实环境验收。

## 已落实的改动

### 员工和坐席

- 首页增加“先找答案”“联系服务台”“开始处理”的任务入口，最近工单可直接打开。
- 工单表单按需展开，补充标题/描述长度限制、分类默认“其他 / 不确定”，优先级同时说明业务影响。
- 修正“提交后自动 AI 分类”的不实文案：当前是按用户选定的分类进入队列。
- 工单查询支持标题、描述、编号搜索，状态、优先级、未解决、分配给我、待指派、超时筛选，最近更新/创建/到期排序。
- 工作台改用分页查询，保留总数，避免把大量工单一次性下载到浏览器；搜索仍在权限条件内进行。
- 增加明确的查看/回复入口，支持从 NEW 直接开始处理；无处理人且操作者属于队列时认领给操作者。
- 通知、新建工单、首页最近工单和问答转人工统一携带工单编号打开详情；旧通知也通过 refId 定位。
- 回复改成多行输入，支持 Ctrl+Enter、两条常用语、AI 草稿插入后编辑；草稿在本页按工单隔离，来回切换保留，**刷新页面后不保证保留**。
- 解决、关闭、重开的说明进入员工可读的评论时间线；评论通知相关人员，并更新工单最近更新时间。
- 请求人关闭/重开后刷新详情与列表；已解决/关闭工单不再继续显示当前超时倒计时。

### 问答可靠性

- 正确使用 Vue 响应式对象接收增量文本，修复可能只能在其他状态变化时才刷新回答的问题。
- 停止立即退出生成状态；取消、异常、提前 EOF、重复终止事件均有处理。
- 识别 CRLF 帧和分片 UTF-8；错误后不自动发送排队问题。
- 用请求序号隔离会话切换、停止后重发与历史加载，避免旧响应写入新会话。
- 回答保存引用；终止事件补充来源、置信字段和持久化引用 ID；历史返回小写消息角色及一致的引用字段。
- 无证据回答返回保存后的消息和会话 ID，可继续查看历史和评价。
- 修复反馈 SQL 中把 comment 错误转换为数组的问题，改用 JDBC 数组绑定；仅能评价自己的助手回答，评分限制为赞/踩。
- 上游输出部分内容后发生异常，或在结束标识前断流时，返回中断状态，不再假装完成。
- 后端结束/超时/错误时关闭上游流并取消任务；发送失败不再被当作普通 JSON 解析失败吞掉。
- 问答转人工先说明共享内容，排除个人笔记引用，并跳转到创建的工单。

### 权限与一致性

- 封堵员工借“重开自己的工单”传入 assigneeId 修改处理人的路径。
- 工单创建、流转、评论使用事务；流转锁定工单后检查状态，避免并发操作都基于旧状态成功。
- AI 动作创建和审批检查状态：未解决不能审批关闭，已解决/关闭不能再次分流；审批关闭调用统一工单流转逻辑。
- 审批时锁定动作及工单，避免重复处理和工单状态变化后仍批准过期动作。
- 停用队列不能继续接收该分类的新工单，返回可理解的错误；非法分类/优先级及超长表单在服务端拒绝。

### 首次使用、性能与布局

- 新增 `scripts/start.ps1`：检查 Docker、生成缺失的本机秘密、保留已有 .env、校验 Compose，顺序构建以减少资源峰值。
- 登录框不再预填管理员账号密码；登录和首次改密后保留目标页面。
- Docker 前端改为 Node 22 + `npm ci`，配合现有锁文件；排除 node_modules/dist 等构建上下文。
- 后端构建去掉耗时的全量依赖预下载步骤，使用 Maven 构建缓存。
- Nginx 请求体限制与 300MB 批次上限对齐，避免代理先拒绝正常的大文件；后端保持单文件 50MB 限制。
- 后端新增健康检查，前端等待后端健康后启动；Compose 传递 Secure Cookie 配置。
- 移除未使用的 Element Plus 全量注册，只加载消息与对话框样式。构建日志对比：主 JS 约 **996.46KB → 243.20KB**（两个主分块之和，约减少 76%），CSS **341.69KB → 55.02KB**（约减少 84%）。这是构建体积，**不是实测加载时间**。
- 修复全局 `.ticket-row` flex 样式作用于表格行的问题，侧栏保持可达，补键盘焦点和文字按钮。
- 390×844 窄屏验收无页面横向溢出，调整问答布局后输入框在首屏可见；提升部分辅助文字对比度。

## 上线前仍需完成

1. **恢复 Docker 后跑真实闭环。** 覆盖代理上传、对象下载、权限隔离、并发关闭、通知、中文知识检索、历史、反馈、文档导入/审核/引用。新脚本覆盖其中的工单与问答回归；原有 e2e/feature 脚本仍依赖特定演示密码，不能假设新装即全部通过。
2. **建立检索质量基线。** 从实际业务整理常见问题、口语问法、无答案问题与跨部门资料，人工标出正确引用；比较当前 FTS、混合检索与后续重排，检查是否答错、引用错、该拒答却回答。当前没有证据证明已达到生产准确率。
3. **做小规模试用。** 让员工和处理人不看操作说明完成真实任务，观察找入口、提问、提单、回复和确认结果时卡在哪里，再决定下一批功能。不能从“新增功能”推断“人们愿意用”。
4. **完善生产运维。** HTTPS、备份恢复演练、默认演示账号治理、通知留存、附件清理、多实例限流、运行告警与负载测试仍需按部署环境实施。
5. **后续产品能力。** 可维护的团队常用回复、满意度、业务时段 SLA、等待用户时暂停计时、工作量分配、知识检索评估界面。当前固定时间 SLA 与简单认领不等价于成熟服务台的完整策略。

上线判断应依据这些验收，而不是旧功能矩阵中的勾选数量。
