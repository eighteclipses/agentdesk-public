## 三、结论

**AgentDesk 的差异化优势**（同类开源项目少见）：
1. **AI 建议→人工审批闭环**：LLM 只建议（分类/草稿/转移/关闭），写入动作必须人审——对比 Chatwoot Captain 的自动化路线，更契合企业合规诉求；
2. **引用可回溯**：每个回答的引用定位到 文件+版本+分块（PDF 带页码），点击可跳转原文位置；
3. **个人知识库与企业知识物理隔离**：Vault 笔记只有"提交审核"才复制为企业草稿，防个人内容污染企业检索；
4. **中文 FTS 原生支持**：CJK 单字+二元分词的纯 SQL 分词器，无 LIKE 兜底；
5. **完整审计链**：Agent 运行、管理动作、SLA 违约全部入库并可导出 CSV。

**本轮补齐**（对齐 Chatwoot/Zammad 的两个最大共性差距）：
- 站内通知中心：工单流转、指派、SLA 首次违约、Agent 审批结论、知识审核结果、账号开通、Vault 投稿提醒；铃铛徽标 + 面板 + 全量历史页。
- 统计图表仪表盘：工单状态/优先级分布、近 N 天新建趋势、SLA 达成率（按期 vs 超时）、问答规模/反馈/引用点击率；零依赖 SVG 图表。

**知识库专项补齐**（对齐 AnythingLLM/RAGFlow 等检索类项目的核心差距）：
- **检索质量**：长查询"单字 AND"召回断崖修复（候选不足自动放宽 OR，按 ts_rank 排序）；检索分页；每文章最多 2 条命中去重；检索结果展示相关度。
- **向量混合检索**：激活预留的 pgvector——agent `/v1/embed`（GLM embedding-3，512 维）+ 导入时向量化 + 存量启动回填 + 查询 RRF 融合；未配置 `AGENT_EMBED_MODEL` 或供应商不支持时自动降级纯 FTS（零硬依赖）。
- **知识全生命周期**：管理员在线编辑（内容变更生成新版本→重新审核，发布版本编辑期间不下线）、手动新建文章 UI、密级（INTERNAL/PUBLIC/CONFIDENTIAL）可设置——CONFIDENTIAL 部门授权检索过滤由此激活。
- **浏览体验**：分类/标签筛选（新字典端点）、管理审核台状态筛选、导入处理事件时间线。
- **缺陷修复**：Chunker 超长段落改按行边界切；docx 解析补表格转换（原实现表格内容全丢）；version 去重策略沿用本批次可见性（原继承旧文章设置）；删除会话后问答反馈改为保留（FK 级联改为 SET NULL，对齐注释语义）。

**剩余扩展点**（按价值排序，均为有意不做并记录在案）：
1. 重排序与查询改写：混合检索之上接 bge-reranker 或 LLM listwise 重排；问答前用 LLM 改写口语化查询；
2. 预设回复/宏：坐席常用语管理，写回复一键插入（后端加一张表 + 前端下拉）；
3. CSAT：工单关闭后请求人评价，纳入统计仪表盘；
4. 自动分配策略：按负载/轮转分配而非"队列首成员"兜底；
5. 分块重叠与语义切分、OCR/ASR 导入（扫描件、语音）、Obsidian 插件同步（P2）、多实例 Redis 限流/SSE（P3）。

**明确不做**：多渠道接入（邮件/社媒收件箱）——超出课程项目定位，AgentDesk 聚焦"企业内部服务台 + 知识库"。
