# 验证边界与结果记录

## 验证分层

| 层级 | 内容 | 是否依赖外部服务 |
| --- | --- | --- |
| Agent 单元测试 | 解析、分块、供应商调用、流式边界、安全包裹 | 否，使用 mock |
| Backend 单元测试 | 工单状态、权限、通知、RRF、Chunker、限流、JWT | 否，主要为纯单元测试 |
| Frontend 确定性测试 | SSE 分片、结束/错误/停止边界 | 否 |

| 冒烟脚本 | 登录、越权、导入、引用、附件、版本 | 需要本地后端/数据库 |
| 端到端回归 | 工单、通知、审计、Agent、统计、知识发布 | 需要完整 Docker Compose |

## 如何记录结果

在公开仓库中，README 只陈述已经实际执行并可复现的结果。一次验证建议保留：

1. 执行日期和工具版本；
2. 命令和退出码；
3. 通过/失败数量；
4. 是否访问真实模型、真实数据库或真实对象存储；
5. 失败是代码问题、环境问题还是未覆盖场景。

不要把“编译通过”写成“全栈功能完整”，也不要把 mock 浏览器验收写成真实模型和真实数据库已经通过。
